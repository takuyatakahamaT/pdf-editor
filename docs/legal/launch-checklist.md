# 商用販売開始チェックリスト

## 権利・法人

- [ ] NIHO株式会社を設立し、登記上の名称を確認する。
- [ ] 創作者とNIHO株式会社の間で、既存のソースコード、UI、アイコン、文書、ビルドスクリプト等を対象とする著作権譲渡契約を締結する。
- [ ] 譲渡人がNIHO株式会社の取締役になる場合、著作権譲渡が利益相反取引に当たるか確認し、会社法上必要な株主総会または取締役会の承認を取る。
- [ ] 会社が使用するNIHO名称、ロゴ、配色などブランド素材の権利または使用許諾を確認する。
- [ ] 外部協力者が参加した場合、成果物の権利帰属・ライセンスを記録する。
- [ ] 本リポジトリが公開であることを踏まえ、会社の秘密情報、署名鍵、認証情報、購入者情報をコミットしない運用を決める。

## 販売条件・顧客対応

- [ ] 特定商取引法の表記に登記上の会社名、住所、連絡可能な電話番号、代表者または通信販売業務責任者を記載する。
- [ ] 商品ページに価格（税込）、追加費用、支払時期・方法、ZIP提供時期、返品・不具合時の条件を表示する。
- [ ] 対応OS・CPU・必要容量などの動作環境、既知の制限を商品ページへ記載する。
- [ ] 購入前にEULAを確認・同意でき、購入後に控えを保存できるようにする。
- [ ] サポート期間、セキュリティ更新の対象、対象外になる時期、問い合わせ窓口を確定する。
- [ ] 決済、メール配信、ファイル配信、問い合わせフォームのデータ処理をプライバシーポリシーへ反映する。
- [ ] 1人が本人管理下の複数Macで利用できること、第三者への再配布・改変を許可しないことを商品ページにも記載する。

## リリース・配布

- [ ] `Resources/Info.plist` のBundle Identifierを販売前に確定し、販売後は維持する。
- [ ] Apple Developer ProgramのDeveloper ID Applicationで、アプリ本体と同梱実行ファイルを署名する。
- [ ] Hardened Runtimeとsecure timestampを使い、ZIP内のアプリをApple notarizationへ提出・stapleする。
- [ ] 複数CPUアーキテクチャを販売する場合、それぞれのMacでビルドし、動作環境とZIP名を一致させる。
- [ ] `scripts/update-third-party-notices.sh` で同梱依存のライセンス・NOTICEを更新する。
- [ ] 販売ZIPをクリーンなMacへ展開し、Gatekeeper表示、初回起動、読込・編集・保存を手動確認する。
- [ ] ZIPのSHA-256、バージョン番号、公開日を更新履歴に記録する。
- [ ] 脆弱性報告の受領、影響確認、修正版の配布、購入者への告知を運用できるようにする。

## 販売開始後の運用

- [ ] 既存購入者の注文・ライセンス・サポート期間を、安全に検索できる形で管理する。
- [ ] 価格変更は新規注文のみへ適用し、購入済み顧客の条件を変えない。
- [ ] サポート終了時は対象バージョンと終了日を事前に告知する。
- [ ] 重大な不具合・脆弱性の窓口と更新履歴を公開する。

## 現状の技術的な販売阻害点

- 現在の自動更新リリースはad-hoc署名です。販売用Developer ID証明書とnotarytoolプロファイルを設定し、`scripts/package-release.sh`で公証済みZIPを作成・検証してください。
- 既存の同梱ライセンスはpdfcpuだけでした。Go依存のライセンス・NOTICE全体を商用配布に含める必要があります。
- 1つのビルドはビルドしたCPUアーキテクチャ向けです。Intel/Apple Silicon向けの販売ZIPを分けるか、Universal buildを構成する必要があります。
- リポジトリが公開でもソース閲覧はできますが、商用ライセンス上の権利移転確認、著作権表示、販売版のコード署名が別途必要です。
